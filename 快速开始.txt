🔍 核心算法解析
================================================================================

1. 空闲块查找算法（连续分配）
   --------------------------------------------------
   输入：需要的块数 block_count
   输出：起始块号（或 -1 表示失败）
   
   算法：
   for start = 0 to (BLOCK_NUM - block_count):
       found = true
       for i = 0 to block_count-1:
           if bit_map[start + i] != 0:
               found = false
               break
       if found:
           return start
   return -1
   
   时间复杂度：O(n²)
   空间复杂度：O(1)

2. 文件创建算法
   --------------------------------------------------
   步骤：
   1. 检查文件名是否已存在
   2. 查找空闲的FCB
   3. 计算需要的块数：block_count = ⌈size / BLOCK_SIZE⌉
   4. 调用 find_free_blocks 分配空间
   5. 在位示图中标记块为已使用（设为1）
   6. 初始化FCB（名称、大小、起始块、有效标志）

3. 文件读写算法
   --------------------------------------------------
   关键：计算磁盘地址
   disk_address = start_block * BLOCK_SIZE
   
   写入：memcpy(&disk[disk_address], data, length)
   读取：memcpy(buffer, &disk[disk_address], length)

4. 文件删除算法
   --------------------------------------------------
   步骤：
   1. 计算文件占用的块数
   2. 在位示图中将这些块标记为空闲（设为0）
   3. 清空磁盘数据（可选）
   4. 将FCB标记为无效

================================================================================
⚠️ 常见问题
================================================================================

Q1: 找不到 GCC 编译器？
A1: 请安装 MinGW-w64 或 TDM-GCC
    下载地址：https://sourceforge.net/projects/mingw-w64/
    安装后将 bin 目录添加到系统 PATH 环境变量

Q2: 编译时出现警告？
A2: 警告通常不影响运行，但如果是错误，请检查：
    - 文件是否完整
    - 编译器版本是否符合要求（GCC 7.0+）

Q3: 运行时出现段错误？
A3: 这不应该发生，如果出现：
    - 检查是否正确编译
    - 使用 GDB 调试：gdb test_fs.exe
    - 检查系统内存是否充足

Q4: 测试失败？
A4: 查看具体失败的测试项，检查：
    - 实现逻辑是否正确
    - 边界条件是否处理
    - 使用 printf 添加调试信息
