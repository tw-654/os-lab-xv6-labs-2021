## 二、实验原理

### 2.1 分页系统基本概念

**分页（Paging）**：将进程的逻辑地址空间划分为固定大小的页面（Page），将物理内存划分为相同大小的帧（Frame），通过页表（Page Table）实现地址映射。

**关键概念**：
- **页面（Page）**：逻辑地址空间的基本单位
- **帧（Frame）**：物理内存的基本单位
- **页表（Page Table）**：页面到帧的映射表
- **页表项（PTE）**：页表中的一个条目，包含帧号和控制位

### 2.2 地址转换过程

```
逻辑地址 = 页号 + 页内偏移
         ↓ 查页表
物理地址 = 帧号 + 页内偏移
```

**计算公式**：
```c
页号 = 逻辑地址 / 页面大小
页内偏移 = 逻辑地址 % 页面大小
物理地址 = 帧号 × 页面大小 + 页内偏移
```

### 2.3 缺页处理

当访问的页面不在物理内存中时，发生**缺页中断（Page Fault）**：

```
1. 检测缺页（valid bit = 0）
2. 查找空闲帧
   - 有空闲帧：分配给新页面
   - 无空闲帧：执行页面置换
3. 从磁盘加载页面到选定的帧
4. 更新页表项
5. 重新执行引发缺页的指令
```

### 2.4 FIFO页面置换算法

**基本思想**：选择最早进入内存的页面进行置换

**算法步骤**：
1. 维护每个页面的进入时间（load_time）
2. 当需要置换时，选择load_time最小的页面
3. 如果被置换页面已修改，先写回磁盘
4. 加载新页面到该帧

**示例**：
```
物理帧数：3
页面访问序列：0, 1, 2, 3, 0, 1, 4

时刻  访问页  物理内存状态     缺页？
1     0      [0, -, -]        是
2     1      [0, 1, -]        是
3     2      [0, 1, 2]        是
4     3      [3, 1, 2]        是（置换0）
5     0      [3, 0, 2]        是（置换1）
6     1      [3, 0, 1]        是（置换2）
7     4      [4, 0, 1]        是（置换3）

缺页次数：7
缺页率：100%
```

## 三、已实现的功能

### 3.1 核心数据结构

#### 页表项结构
```c
typedef struct page_table_entry {
    int frame_num;          // 物理帧号（-1表示未分配）
    bool valid;             // 有效位（是否在内存中）
    bool modified;          // 修改位（是否被写过）
    bool referenced;        // 访问位（是否被访问）
    int load_time;          // 加载时间（用于FIFO）
} pte_t;
```

#### 分页系统管理器
```c
typedef struct {
    pte_t page_table[MAX_PAGES];         // 页表（256项）
    frame_info_t frames[MAX_FRAMES];     // 物理帧信息（4帧）
    char physical_memory[MAX_FRAMES][PAGE_SIZE]; // 物理内存
    int page_fault_count;                // 缺页统计
    int memory_access_count;             // 访问统计
    int current_time;                    // 时间戳
} paging_system_t;
```

### 3.2 核心函数

#### 1. translate_address() - 地址转换
```c
int translate_address(paging_system_t *ps, int logical_addr, char operation);
```
- 功能：将逻辑地址转换为物理地址
- 参数：
  - `ps`：分页系统指针
  - `logical_addr`：逻辑地址
  - `operation`：操作类型（'R'读 / 'W'写）
- 返回：物理地址（失败返回-1）

**实现要点**：
1. 分解逻辑地址为页号和偏移
2. 检查页表项的有效位
3. 如果无效，调用缺页处理
4. 更新访问位和修改位
5. 计算并返回物理地址

#### 2. handle_page_fault() - 缺页处理
```c
void handle_page_fault(paging_system_t *ps, int page_num);
```
- 功能：处理缺页中断
- 步骤：
  1. 增加缺页计数
  2. 查找空闲帧
  3. 如果无空闲帧，调用置换算法
  4. 加载新页面
  5. 更新页表

#### 3. fifo_replace() - FIFO置换算法 ⭐
```c
int fifo_replace(paging_system_t *ps);
```
- 功能：选择要被置换的页面
- 算法：找到load_time最小的帧
- 返回：被选中的帧号

**核心代码**：
```c
int fifo_replace(paging_system_t *ps) {
    int oldest_frame = 0;
    int oldest_time = ps->frames[0].load_time;
    
    // 找到加载时间最早的帧
    for (int i = 1; i < MAX_FRAMES; i++) {
        if (ps->frames[i].load_time < oldest_time) {
            oldest_time = ps->frames[i].load_time;
            oldest_frame = i;
        }
    }
    
    return oldest_frame;
}
```

#### 4. 辅助函数
- `find_free_frame()`：查找空闲帧
- `update_page_table()`：更新页表项
- `load_from_disk()`：从磁盘加载页面
- `save_to_disk()`：写回磁盘

### 3.3 统计和显示函数

## 六、关键知识点

### 6.1 地址转换机制

**逻辑地址结构**（32位系统，4KB页面）：
```
|  页号 (20 bits)  |  页内偏移 (12 bits)  |
```

**地址转换过程**：
```
1. CPU产生逻辑地址
2. MMU分解地址为页号和偏移
3. 查页表获取帧号
4. 如果有效位=1，组合帧号和偏移得到物理地址
5. 如果有效位=0，触发缺页中断
```

### 6.2 页表项控制位

- **有效位（Valid Bit）**：
  - 1：页面在内存中
  - 0：页面不在内存中（触发缺页）

- **修改位（Modified/Dirty Bit）**：
  - 1：页面被修改过，置换时需写回
  - 0：页面未修改，置换时可直接丢弃

- **访问位（Referenced Bit）**：
  - 1：页面被访问过
  - 0：页面未被访问（用于LRU等算法）

### 6.3 FIFO算法特性

**优点**：
- ✅ 实现简单
- ✅ 开销小
- ✅ 公平性好

**缺点**：
- ❌ 性能不佳（可能置换常用页面）
- ❌ 存在Belady异常（增加帧数反而增加缺页）
- ❌ 不考虑页面使用情况

**Belady异常示例**：
```
访问序列：1,2,3,4,1,2,5,1,2,3,4,5

3帧时缺页：9次
4帧时缺页：10次（更多！）
```

## 七、性能分析

### 7.1 缺页率计算

```
缺页率 = (缺页次数 / 总访问次数) × 100%
命中率 = 100% - 缺页率
```

### 7.2 影响因素

1. **物理帧数量**：
   - 帧数越多，缺页率通常越低
   - 但FIFO存在Belady异常

2. **页面访问模式**：
   - 顺序访问：缺页率较低
   - 随机访问：缺页率较高
   - 局部性好：缺页率低

3. **工作集大小**：
   - 工作集 < 帧数：缺页率低
   - 工作集 > 帧数：频繁置换

## 九、常见问题

### Q1：为什么物理帧只有4个？
A：为了便于观察和测试页面置换过程。在真实系统中，物理帧数量通常很大（几千到几百万）。

### Q2：为什么页面大小是4KB？
A：4KB是最常见的页面大小，平衡了内存碎片和页表大小。现代系统也支持2MB、1GB等大页面。

### Q3：FIFO算法为什么会有Belady异常？
A：因为FIFO只考虑进入顺序，不考虑使用情况。增加帧数可能改变页面进入顺序，反而导致更多冲突。

### Q4：修改位有什么用？
A：避免不必要的磁盘写入。如果页面未被修改，置换时可以直接丢弃，不需要写回磁盘。
