# 实验一测试结果分析报告

## 测试结果概述

### 总体表现
- **三种算法表现完全相同**：First Fit、Best Fit、Worst Fit 在本次测试中产生了完全相同的分配结果
- **分配成功率**：100%（7/7次分配全部成功）
- **最终状态**：所有内存成功释放，无碎片残留

## 详细分析

### 1. 分配阶段分析

#### 内存分配序列
```
测试序列: {50, 30, 20, 40, 60, 10, 25} KB
总内存: 256 KB
```

#### 分配过程
1. **分配50 KB** → 地址0，剩余206 KB（连续）
2. **分配30 KB** → 地址50，剩余176 KB（连续）
3. **分配20 KB** → 地址80，剩余156 KB（连续）
4. **分配40 KB** → 地址100，剩余116 KB（连续）
5. **分配60 KB** → 地址140，剩余56 KB（连续）
6. **分配10 KB** → 地址200，剩余46 KB（连续）
7. **分配25 KB** → 地址210，剩余21 KB（连续）

#### 关键观察
- **所有分配阶段碎片为0**：因为始终只有一个连续的大空闲分区
- **三种算法行为相同的原因**：
  - 在分配阶段，空闲链表始终只有一个节点
  - First Fit：找到第一个（也是唯一的）满足条件的分区
  - Best Fit：找到最小的满足条件的分区（也是唯一的）
  - Worst Fit：找到最大的满足条件的分区（也是唯一的）
  - **结果**：三种算法都选择同一个分区，行为完全一致

### 2. 释放阶段分析

#### 释放过程
释放顺序与分配顺序相同（FIFO释放）：
```
释放[0,50) → 产生两个分区：[0,50)和[235,256)，碎片21 KB
释放[50,80) → 合并为[0,80)，碎片仍为21 KB
释放[80,100) → 合并为[0,100)，碎片仍为21 KB
释放[100,140) → 合并为[0,140)，碎片仍为21 KB
释放[140,200) → 合并为[0,200)，碎片仍为21 KB
释放[200,210) → 合并为[0,210)，碎片仍为21 KB
释放[210,235) → 最终合并为[0,256)，碎片0 KB
```

#### 碎片产生分析
- **碎片产生时机**：第一次释放后，内存被分割为两部分
  - 低地址区：[0, 50) - 50 KB
  - 高地址区：[235, 256) - 21 KB
- **碎片大小**：21 KB（最大空闲分区为50 KB，总空闲71 KB，碎片=71-50=21）
- **碎片持续存在**：直到最后一个块释放，两个分区才合并

### 3. 算法性能对比

#### 为什么三种算法表现相同？

**原因分析**：
1. **测试序列特性**：
   - 所有分配请求都是顺序执行的
   - 在分配阶段，空闲链表始终只有一个大分区
   - 三种算法在单分区情况下行为必然相同

2. **算法差异未体现**：
   - **First Fit vs Best Fit vs Worst Fit** 的差异主要体现在**多个空闲分区**时的选择策略
   - 本次测试在分配阶段没有产生多个空闲分区，因此差异无法体现

#### 预期差异场景

三种算法在以下场景会产生不同结果：

**场景1：非顺序分配**
```
初始：256 KB空闲
分配50 KB → 剩余206 KB
分配100 KB → 剩余106 KB
释放50 KB → 产生两个分区：[0,50)和[100,256)
分配30 KB：
  - First Fit: 选择[0,50)，剩余[20,50)和[100,256)
  - Best Fit: 选择[0,50)，剩余[20,50)和[100,256)
  - Worst Fit: 选择[100,256)，剩余[0,50)和[130,256)
```

**场景2：不同大小的空闲分区**
```
空闲分区：[0,20), [50,100), [150,256)
分配30 KB：
  - First Fit: 选择[50,100)，剩余[0,20), [80,100), [150,256)
  - Best Fit: 选择[50,100)，剩余[0,20), [80,100), [150,256)
  - Worst Fit: 选择[150,256)，剩余[0,20), [50,100), [180,256)
```

### 5. 算法特性总结

#### First Fit（首次适应）
- **本次表现**：100%成功率，无碎片（分配阶段）
- **特点**：实现简单，分配速度快
- **适用场景**：内存充足，分配请求频繁

#### Best Fit（最佳适应）
- **本次表现**：与First Fit相同
- **特点**：减少大分区浪费，但易产生小碎片
- **适用场景**：内存紧张，需要最大化利用

#### Worst Fit（最坏适应）
- **本次表现**：与First Fit相同
- **特点**：减少小碎片，但大分区消耗快
- **适用场景**：希望保持大块连续内存

### 6. 结论

1. **实现正确性**：三种算法实现正确，功能完整
2. **测试局限性**：当前测试序列未能体现算法差异
3. **实际应用**：在真实场景中，三种算法会产生不同的内存布局和碎片情况
4. **改进建议**：需要设计更复杂的测试场景来验证算法差异
